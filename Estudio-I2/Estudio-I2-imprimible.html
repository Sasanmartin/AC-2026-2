Cheatsheet 1 · Subrutinas (P1)

Cheatsheet 1 — Subrutinas en el computador básico (P1)

Lo que se pregunta: implementar 1–3 instrucciones nuevas (hardware + tabla de señales), y simular 2 fragmentos de código con CALL, RET, PUSH, POP y stack.

1. Idea y requisitos

Una subrutina necesita:

  1. Parámetros de entrada → en este curso se guardan en memoria/stack (los registros A y B no alcanzan).
  2. Valor de retorno → también en memoria/stack.
  3. Llamada y retorno → hay que guardar la dirección de retorno (PC+1) para poder volver.

El stack permite llamadas anidadas y recursión sin que las variables choquen.

2. Layout de memoria y stack

Direcciones bajas
┌─────────────────────────────┐
│ DATA / variables            │
├─────────────────────────────┤
│ ...                         │
│ stack (crece hacia abajo)   │
│ SP+1 = tope del stack       │
│ SP   = próximo espacio libre│
└─────────────────────────────┘
Dirección 255 = primera celda del stack
  • SP parte en 255.
  • PUSH: Mem[SP] ← valor; SP ← SP−1.
  • POP: SP ← SP+1; valor ← Mem[SP].
  • CALL: Mem[SP] ← PC+1; SP ← SP−1; PC ← label.
  • RET: SP ← SP+1; PC ← Mem[SP].
  • Por eso SP apunta al siguiente espacio libre, y el tope real es SP+1.
  • Si el stack crece demasiado y choca con las variables → stack overflow.

3. Modificaciones de hardware típicas

Componente Para qué sirve
Mux DataIn (SDIn)Elegir qué se escribe en memoria: resultado de la ALU o PC+1 (para CALL).
Mux PC (SPC)Elegir qué se carga en PC: literal/label (LIT) o dato de memoria (DOUT, para RET).
Mux Address (SAdd)Elegir la dirección de memoria: LIT, B, SP o ADDER. Necesita 2 bits si hay 3–4 entradas.
Mux Adder (SAdder)Elegir la entrada del Adder: PC o SP. Permite calcular PC+1 o SP+1.
SP + IncSP / DecSPIncrementar/decrementar el stack pointer.
Registro RA (opcional, 2024-2)Guardar la dirección de retorno en un registro (LRA, SRA) en vez del stack.

El truco del SP+1

SP apunta al próximo espacio libre, pero el tope del stack es SP+1. Para leer o escribir el tope sin mover SP se usa:

  • SAdder = SP → el Adder calcula SP+1.
  • SAdd = ADDER → se usa SP+1 como dirección de memoria.

Esto es lo que permite RET1, PUSHRW, POPRD y POP1 en un solo ciclo.

4. Semántica y señales de las instrucciones

Convención: en cargas/escrituras 1 = activo, 0 = inactivo; en selecciones, el nombre de la entrada (LIT, SP, DOUT, ALU, ADDER, ZERO, B, etc.) o - si no importa.

Instrucción Operación Ciclos Señales principales

RETSP++; PC ← Mem[SP]2Ciclo 1: IncSP=1 · Ciclo 2: SAdd=SP, SPC=DOUT, LPC=1
PUSH AMem[SP] ← A; SP−−1W=1, DecSP=1, SAdd=SP, SDIn=ALU, SA=A, SB=ZERO, SOP=ADD

Ojo: los nombres exactos de las entradas de los mux dependen del diagrama que entregue el enunciado. La pauta acepta la combinación coherente; lo importante es que la operación se ejecute en un ciclo y que la tabla sea completa.

5. Patrón para implementar una instrucción nueva

  1. ¿Qué falta? ¿Un dato que no llega a la ALU? ¿Una dirección que el Mux Address no puede elegir? ¿Un registro nuevo? ¿Un valor que hay que escribir en memoria?
  2. Modificación mínima:
  3. Nuevo registro R → señal LR.
  4. Nueva entrada a un mux → agregar entrada y ampliar el selector (SA, SB, SPC, SAdd).
  5. Nuevo dato a memoria → conectar al Mux DataIn y usar SDIn.
  6. Necesitas SP+1 → usar Mux Adder + SAdder=SP.
  7. Completa la fila: LA, LB, LPC, IncSP, DecSP, W, SA, SB, SOP, SAdd, SDIn, SPC, SAdder.
  8. ¿Se puede sin hardware? Si sí, dilo explícitamente y usa las señales existentes. Si no, indica una sola modificación que habilite todas las instrucciones del enunciado.
  9. Verifica los ciclos: el enunciado suele exigir 1 ciclo. Si tu solución necesita 2, probablemente haya que agregar el Mux Adder o conectar una salida a un mux.

Ejemplo de razonamiento: RET1 en 1 ciclo

RET normal necesita 2 ciclos porque primero hay que hacer SP++ y después leer Mem[SP]. Para hacerlo en 1 ciclo:

  • El Adder calcula SP+1 (con SAdder=SP).
  • El Mux Address elige ADDER (SAdd=ADDER).
  • El Mux PC elige DOUT (SPC=DOUT).
  • IncSP=1 actualiza SP al mismo tiempo.

Así se lee Mem[SP+1] y se carga en PC en el mismo ciclo. Esa es la idea que más se repite.

6. Método de simulación (para “indique A y B al final”)

  1. Copia las direcciones que da el enunciado. No inventes direcciones.
  2. Haz una tabla por instrucción:

# | Instr | A | B | Mem afectada | SP | PC | flags

  1. Respeta el tamaño de cada instrucción en el listado:
Instrucción Celdas típicas
MOV, ADD, SUB, CMP, JMP, saltos condicionales1
CALL, PUSH1
POP, RET2

Usa siempre las direcciones del enunciado; la tabla anterior es solo una referencia.

  1. CALL guarda PC+1 (la dirección de la instrucción siguiente). Si CALL está en 0x04, guarda 0x05, no 0x04.
  2. RET hace SP++ y salta a Mem[SP]. Si alguien sobrescribió esa celda, salta a otra parte.
  3. Las flags las actualiza la última operación que las modifique. Un CMP seguido de otra instrucción que cambie flags puede arruinar el salto condicional.
  4. MOV (B),A escribe en Mem[B]. Si B apunta al stack, puedes pisar la dirección de retorno.
  5. JMP (B) salta a Mem[B]; JMP B salta a B (si la instrucción existe).
  6. Al final, revisa A, B, SP y la memoria relevante; el enunciado suele pedir solo A y B, pero el desarrollo debe justificar cómo llegaste.

7. Ejemplo resuelto — pisar la dirección de retorno (I2 2026-1)

MOV A,2
MOV B,5
PUSH A          ; Mem[255]=2, SP=254
PUSH B          ; Mem[254]=5, SP=253
CALL mystery    ; Mem[253]=0x05, SP=252
POP B           ; no se ejecuta
POP A           ; no se ejecuta
JMP end
mystery:
MOV A,0
NOT A,A         ; A=255
SUB A,2         ; A=253
MOV B,A         ; B=253
MOV A,(B)       ; A=Mem[253]=0x05=5
ADD A,4         ; A=9
MOV (B),A       ; Mem[253]=9
RET             ; SP=253, PC=Mem[253]=9 → JMP end
end:

Resultado: A = 9, B = 253. La subrutina no vuelve a POP B, sino que salta a JMP end porque sobrescribió su propia dirección de retorno. Este patrón aparece mucho.

8. Errores que más castigan

  • Poner LPC=1 por defecto en instrucciones que no saltan.
  • Olvidar W=1 cuando se escribe memoria.
  • Confundir PUSH (escribe y luego decrementa) con POP (incrementa y luego lee).
  • Decir que RET es de 1 ciclo sin agregar el Mux Adder.
  • No conectar SP al Mux A o al Mux B y aun así usar MOV A,SP o CMP B,SP.
  • No indicar la condición en saltos condicionales (LPC depende de Z/N, no es 1 fijo).
  • Olvidar que CALL guarda PC+1, no PC.
  • No revisar si el código pisa el stack con MOV (B),A o PUSH.
  • En la simulación, saltarse instrucciones que no se ejecutan: marca explícitamente “no se ejecuta”.

Cheatsheet 2 · Floats IEEE754 (P2)

Cheatsheet 2 — Floats IEEE754 (P2)

Lo que se pregunta: interpretar números en hex, sumar/multiplicar, indicar el resultado en binario normalizado y decidir si se pierde precisión al guardarlo como float. También caen preguntas cortas de teoría (bits de precisión, exponentes, punto fijo vs flotante).

1. Punto fijo vs punto flotante

Representación Ventaja Desventaja
Punto fijoSimple, rápido, predecible.Rango muy pequeño; poca precisión relativa.
Punto flotanteRango mucho más amplio (exponente).Menos precisión; errores de redondeo.

En punto fijo los bits se reparten en signo, parte entera y parte fraccionaria fija. En punto flotante se representa como significante × base^exponente, así que el punto “flota”.

2. Formato IEEE754 de 32 bits (float)

 1 bit      8 bits              23 bits
┌──────┬────────────────┬──────────────────────────┐
│  S   │  E (sesgo 127) │  M (significando)        │
└──────┴────────────────┴──────────────────────────┘
  31      30 ... 23         22 ... 0
  • Signo S: 0 = positivo, 1 = negativo.
  • Exponente E: 8 bits, sesgado en 127. Exponente real e = E − 127.
  • Significando M: 23 bits, pero se asume un 1 implícito a la izquierda: 1.M.
  • Precisión total: 24 bits (23 explícitos + 1 implícito).
  • Valor: X = (−1)^S × 1.M × 2^(E−127).

Rango y casos especiales

Exponente E Significando M Significado
00000000000...0±0 (+0 = 0x00000000, −0 = 0x80000000)
00000000≠ 0Número subnormal (no normalizado)
00000001 a 11111110cualquieraNúmero normal, e ∈ [−126, 127]
11111111000...0±∞ (+∞ = 0x7F800000, −∞ = 0xFF800000)
11111111≠ 0NaN (Not a Number)
  • Exponentes distintos representables: 254 (256 − 2 reservados: 0 y 255).
  • Precisión: 24 bits.
  • double (64 bits): 1 signo + 11 exponente (sesgo 1023) + 52 significando → 53 bits de precisión.
  • εmach de float ≈ 2^-23; de double ≈ 2^-52.

3. Conversión decimal → float

  1. Pasa la parte entera y fraccionaria a binario.
  2. Normaliza: 1.xxxx × 2^e.
  3. Calcula E = e + 127 en binario (8 bits).
  4. Escribe S | E | M (M son los bits después del punto, sin el 1 implícito).
  5. Agrupa de a 4 bits para obtener el hex.

Ejemplo: 0.15625

  • 0.15625 = 0.00101₂ = 1.01₂ × 2^-3.
  • e = −3 → E = 124 = 01111100₂.
  • S = 0, M = 010000....
  • Resultado: 0 01111100 01000000000000000000000 = 0x3E200000.

Ejemplo: −1.6875

  • 1.6875 = 1.1011₂.
  • e = 0 → E = 127 = 01111111₂.
  • S = 1, M = 101100....
  • Resultado: 1 01111111 10110000000000000000000 = 0xBFD80000.

4. Conversión float → decimal

  1. Pasa el hex a binario (4 bits por dígito).
  2. Separa S | E | M.
  3. Calcula e = E − 127.
  4. Escribe 1.M × 2^e y pasa a decimal.
  5. Si E = 255, revisa si es ±∞ o NaN; si E = 0, revisa cero/subnormal.

Ejemplo: 0xBF800000

  • 1 01111111 00000000000000000000000.
  • S=1, E=127 → e=0, M=0 → 1.0.
  • Valor: −(1.0 × 2^0) = −1.

5. Suma de floats

Algoritmo:

  1. Comparar exponentes. Si son distintos, toma el de menor exponente y hazle shift right al significando, aumentando su exponente de a 1 hasta igualar al mayor.
  2. Sumar los significandos (manteniendo el exponente).
  3. Normalizar: si queda 1x.xxx, shift right y e+1; si queda 0.xxx, shift left y e−1.
  4. Redondear a 23 bits (o 24 con el implícito). Si al redondear se desnormaliza, repetir.
  5. Verificar el resultado en decimal.

Ejemplo: A = 1.11₂ × 2^3 = 14, C = 1.11₂ × 2^1 = 3.5

C = 1.11 × 2^1
  = 0.111 × 2^2
  = 0.0111 × 2^3        (shift right 2 veces)

A + C = 1.11 × 2^3 + 0.0111 × 2^3
      = 10.0011 × 2^3
      = 1.00011 × 2^4    (normalizo: shift right, e+1)
      = 10001.1₂ = 17.5

Si los dos números tienen el mismo exponente, sáltate el paso 1.

6. Multiplicación de floats

Algoritmo:

  1. Sumar exponentes. Si están sesgados: E_resultado = E_A + E_B − 127. Si no están sesgados: e_resultado = e_A + e_B.
  2. Multiplicar significandos (ignora el punto; luego ubícalo contando posiciones).
  3. Normalizar el producto (shift right/left y ajustar exponente).
  4. Redondear a 23 bits.
  5. Signo: S_resultado = S_A XOR S_B.

Ejemplo: A = 1.11₂ × 2^3 = 14, B = 1.1₂ × 2^3 = 12

Exponente: 3 + 3 = 6
Significandos:
      1.110
   ×  1.100
   ---------
     10.101  (producto binario)

Normalizo: 1.0101 × 2^7  →  10101000₂ = 168

Con sesgo: E_A = 3+127 = 130, E_B = 130 → E_resultado = 130+130−127 = 133 → e = 133−127 = 6. Correcto.

7. Pérdida de precisión

  • Un float solo guarda 24 bits de significando. Si el resultado exacto necesita más, se pierden los bits menos significativos.
  • ¿Se pierde precisión? Compara el resultado exacto con el que queda almacenado. Si son distintos → sí. Indica cuántos bits se pierden y su peso (ej. 2^-5 = 0.03125).
  • ¿Es exactamente representable? Un número lo es si puede escribirse como m × 2^e con m entero de a lo más 24 bits (en el rango normal).
  • 2^70 → sí (potencia de 2).
  • 2^50 + 1 → no: necesita 51 bits; el 1 se pierde.
  • 2^24 + 1 → no: necesita 25 bits; el 1 se pierde.
  • 2^26 + 2 → no: necesita 26 bits; el 2 se pierde.
  • 0.1 → no: en binario es infinito periódico.
  • Redondeo: truncado, hacia arriba/abajo o al par más cercano. El curso suele aceptar truncado si lo indicas.
  • εmach: distancia entre 1 y el siguiente float; mide el error relativo máximo. Para float es 2^-23; para double, 2^-52.

8. Frases de teoría que conviene tener listas

Pregunta Respuesta corta
¿Cuántos bits de precisión tiene un float?24: 23 del significando + 1 implícito.
¿Cuántos exponentes distintos?254: 256 combinaciones menos 0 y 255.
¿Por qué se usa sesgo 127?Para representar exponentes negativos sin bit de signo ni complemento a 2.
¿Punto fijo vs flotante?Fijo: más simple/rápido, poco rango. Flotante: más rango, menos precisión.
¿Se pierde precisión al guardar?Sí si el resultado exacto necesita más de 24 bits de significando.
¿Qué es NaN?Exponente 255 y significando ≠ 0; resultado de operaciones inválidas (0/0, ∞−∞).
¿Qué es ±∞?Exponente 255 y significando 0; se obtiene al desbordar o dividir por 0.

9. Errores típicos

  • Aplicar el sesgo al revés: al guardar se suma 127; al leer se resta 127.
  • Olvidar el 1 implícito al interpretar el significando.
  • Sumar exponentes sin restar el sesgo en la multiplicación.
  • Normalizar mal: 10.xxx × 2^e = 1.0xxx × 2^(e+1), no 2^(e−1).
  • Decir “no se pierde precisión” cuando el resultado exacto tiene más de 24 bits.
  • Confundir NaN con ∞: ∞ tiene significando 0; NaN tiene significando distinto de 0.
  • En la suma, olvidar hacer shift right al número de menor exponente (no al mayor).
  • No indicar el resultado en binario normalizado cuando el enunciado lo exige.

Cheatsheet 3 · I/O (P3)

Cheatsheet 3 — I/O (P3)

Lo que se pregunta: comparar memory-mapped vs port-mapped, explicar el address decoder, polling vs interrupciones vs DMA, y describir por estados/comandos un código RISC-V que maneja un dispositivo.

1. Memory-mapped vs port-mapped

Memory-mapped I/O Port-mapped / isolated I/O
Espacio de direccionesEl mismo que la RAM.Espacio separado de I/O.
InstruccionesLas normales: lw, sw, lb, sb.Especiales: IN, OUT (x86).
DecodificaciónAddress decoder distingue RAM vs dispositivo por la dirección.La CPU distingue por un pin o bus de I/O separado.
ISANo hay que cambiar la ISA.Hay que agregar instrucciones o un modo de I/O.
VentajaSimple, flexible, funciona con cualquier instrucción de load/store.No consume espacio de memoria; puede ser más rápido para device registers.
DesventajaOcupa direcciones de memoria; puede chocar con RAM.Menos flexible; requiere hardware/ISA especial.
Uso típicoRISC-V, ARM, la mayoría de sistemas embebidos.x86 (histórico).

En RISC-V no existen IN/OUT: todo I/O es memory-mapped. Por eso el código de la P3 usa lw/sw con una dirección base y offsets.

¿Por qué memory-mapped simplifica el hardware?

Porque el CPU sigue haciendo exactamente lo mismo: pone una dirección en el bus, activa lectura o escritura y mueve datos. El address decoder decide si esa dirección pertenece a RAM o a un dispositivo. No hay que agregar instrucciones ni un bus separado.

2. Address decoder

El decoder está entre el bus de direcciones/control y la RAM + dispositivos.

Entradas:

  • Dirección (Address).
  • Señal de escritura/lectura (W, Read).
  • A veces Request/Valid.

Salidas:

  • Chip Select de la RAM.
  • Chip Select de cada dispositivo.
  • Selección del registro interno del dispositivo (status, data, control).

Funcionamiento:

  1. Compara la dirección con el rango asignado a cada dispositivo.
  2. Activa solo el Chip Select correspondiente.
  3. Si es escritura, habilita la escritura del registro; si es lectura, pone el dato en el bus.

¿Por qué va solo ahí? Porque es el único punto donde se decide a quién va dirigida la operación. El resto del CPU no necesita saber si habla con RAM o con un dispositivo: sigue ejecutando lw/sw normalmente. Si el decoder estuviera en otro lado, habría que duplicar lógica de selección en el datapath.

3. Polling (consulta repetida)

La CPU pregunta en un loop si el dispositivo está listo:

loop:
    leer status
    si no está listo → volver a loop
    leer/escribir dato
  • Ventaja: no requiere hardware de interrupciones; simple.
  • Desventaja: la CPU desperdicia ciclos esperando; no puede hacer otra cosa.
  • Cuándo conviene: dispositivos simples, lentos o de baja frecuencia; sistemas donde el CPU no tiene otra tarea. USB usa polling del host sobre el bus.
  • Cuándo no conviene: disco, red, teclado en un sistema multiusuario; ahí se usan interrupciones o DMA.

4. Interrupciones

Idea

El dispositivo avisa a la CPU cuando necesita atención. La CPU termina la instrucción actual, guarda su estado y salta a una rutina de servicio de interrupción (ISR). Al terminar, vuelve exactamente a donde estaba.

Pasos (sin controlador dedicado)

  1. El dispositivo activa IRQ.
  2. La CPU termina la instrucción actual y guarda las condition codes.
  3. Revisa IF (Interrupt Flag):
  4. IF = 0 → la interrupción queda pendiente o se ignora.
  5. IF = 1 → continúa.
  6. IF = 0 para evitar interrupciones anidadas (si no se permiten).
  7. Guarda el estado (PC, registros) y salta a la ISR.
  8. La ISR guarda los registros que va a usar.
  9. Ejecuta el servicio (leer dato, escribir comando, limpiar flag).
  10. Restaura registros.
  11. IRET/RET vuelve a la instrucción siguiente.
  12. IF = 1 y se restauran las condition codes.

Pasos (con controlador de interrupciones)

  1. Dispositivo activa IRQ.
  2. El controlador revisa máscara y prioridad.
  3. Si corresponde, activa INT hacia la CPU y marca el pedido como in-service.
  4. La CPU termina la instrucción, guarda estado y activa INTA (Interrupt Acknowledge).
  5. El controlador entrega el ID del dispositivo de mayor prioridad.
  6. La CPU usa el ID para indexar la tabla de vectores y saltar a la ISR.
  7. La ISR atiende y escribe EOI (End Of Interrupt) al controlador.
  8. El controlador limpia el bit in-service y puede atender el siguiente.

Señales y conceptos

Tipos

  • Externa / hardware: la genera un dispositivo (teclado, disco, timer).
  • Interna / software: ecall, INT n, traps.
  • Excepción: síncrona, causada por la instrucción actual (división por cero, acceso inválido, desbordamiento, instrucción ilegal).

Ventajas y desventajas

  • Ventaja: la CPU no espera; atiende solo cuando hace falta.
  • Desventaja: más hardware (controlador, vectores), más complejidad, latencia e impredecibilidad.
  • Latencia de interrupción: tiempo desde IRQ hasta la primera instrucción de la ISR. Aumenta si IF=0, si hay una instrucción larga o si hay varias interrupciones de mayor prioridad.

5. DMA (Direct Memory Access)

El controlador DMA mueve datos entre memoria y dispositivo sin que la CPU copie byte por byte.

Funcionamiento

  1. La CPU programa el DMA:
  2. dirección de origen,
  3. dirección de destino,
  4. cantidad de words/bytes,
  5. dirección (lectura/escritura),
  6. modo (burst o cycle stealing).
  7. La CPU le dice “parte” y sigue ejecutando.
  8. El DMA pide el bus de memoria (o lo toma por ciclos).
  9. Transfiere los datos.
  10. Al terminar, genera una interrupción para avisar.

Modos

  • Burst: el DMA toma el bus y transfiere un bloque completo; la CPU queda bloqueada.
  • Cycle stealing: el DMA “roba” ciclos de memoria entre accesos de la CPU; más lento pero no bloquea.

Ventajas / desventajas

  • Ventaja: libera a la CPU de copiar datos; ideal para discos, red, audio, video.
  • Desventaja: hardware extra; compite por el bus; puede complicar la coherencia de caché.

En este curso, DMA se usa con I/O mapeada en memoria, porque el controlador necesita direcciones de memoria para leer/escribir.

7. I/O en RISC-V

Direcciones y offsets

  • Los registros de un dispositivo suelen ser de 32 bits → cada uno ocupa 4 bytes.
  • Si la base es 0x00FF10AD, los registros están en base+0, base+4, base+8, ...
  • En RISC-V no se puede hacer lw t0, t1: el load/store usa offset(base): lw t0, 0(t1), sw t2, 4(t1).

Patrón de polling

# t0 = dirección base del dispositivo
loop:
    lw   t1, 0(t0)       # lee status
    andi t1, t1, 1       # bit 0 = "listo"
    beq  t1, zero, loop  # si no está listo, espera
    lw   t2, 4(t0)       # lee dato
    sw   t2, 8(t0)       # escribe comando / dato
    j    loop

Patrón con interrupción (conceptual)

# La ISR:
    lw   t1, 0(t0)       # status
    lw   t2, 4(t0)       # dato
    sw   t2, 8(t0)       # respuesta
    sw   zero, 12(t0)    # limpiar flag / EOI
    mret                 # o ret, según el sistema

Cómo describir el código (lo que pide la P3)

No traduzcas línea por línea. Describe estados y comandos:

  1. Estado inicial: “El programa configura la base del dispositivo y entra en espera.”
  2. Estado de espera: “Lee el registro de status y repite mientras el bit de ‘listo’ sea 0.”
  3. Estado de lectura: “Cuando está listo, lee el dato desde base+4.”
  4. Estado de comando: “Escribe una orden en base+8 para mover el robot / imprimir.”
  5. Estado de repetición: “Vuelve a esperar el siguiente dato.”
  6. Si hay varios step_*, nómbralos: step_wait, step_read, step_write, step_error.

Ejemplo de frase: “step_wait consulta el bit 0 de status; cuando vale 1, step_read lee el byte de dato y step_cmd escribe el comando en el registro de control. Luego vuelve a step_wait.”

Pregunta Respuesta

¿Dónde va el decoder?Entre el bus y la memoria/dispositivos; es el único punto de selección.
¿Polling vs interrupción?Polling espera activamente; interrupción avisa y libera a la CPU.

9. Errores típicos

  • Decir que memory-mapped “no ocupa memoria”: sí ocupa direcciones.
  • Confundir port-mapped con memory-mapped.
  • Creer que el address decoder está dentro de la ALU o del CPU: está en el bus.
  • Decir que polling es “más rápido” que interrupciones: puede ser más simple, pero desperdicia CPU.
  • Olvidar que la ISR debe limpiar el flag o hacer EOI; si no, la interrupción se repite.
  • No guardar/restaurar registros en la ISR.
  • Usar lw t0, t1 en RISC-V: falta offset(base).
  • Usar offsets de 1 byte cuando los registros son de 4 bytes.
  • Describir el código RISC-V línea por línea en vez de por estados/comandos.
  • Ignorar el bit de status y leer el dato antes de que esté listo.

Cheatsheet 4 · RISC-V (P3)

Cheatsheet 4 — RISC-V (P3)

Lo que se pregunta: leer/escribir código RISC-V, entender la convención de llamada, identificar qué hace una función y manejar registros/stack. En I2 suele venir junto con I/O.

1. Modelo mental

  • ISA load/store: solo lw/sw (y variantes) acceden a memoria. Las operaciones aritméticas son registro-registro o registro-inmediato.
  • 32 registros de 32 bits (x0–x31). x0 siempre vale 0.
  • PC separado; no hay registro de flags. Los branches comparan dos registros directamente: beq rs1, rs2, label.
  • Little-endian.
  • Instrucciones de 32 bits, alineadas a 4 bytes.
  • No hay IN/OUT: el I/O es memory-mapped (lw/sw a direcciones de dispositivo).

5. Convención de llamada

Argumentos y retorno

  • Primeros 8 argumentos: a0–a7.
  • Argumentos adicionales: en el stack, en orden.
  • Retorno: a0 (y a1 si es de 64 bits).
  • ra guarda la dirección de retorno.

Stack frame típico

func:
    addi sp, sp, -16       # reserva 16 bytes (múltiplo de 16)
    sw   ra, 12(sp)        # guarda return address
    sw   s0, 8(sp)         # guarda registros callee-saved que uses
    sw   s1, 4(sp)
    # ... cuerpo de la función ...

    lw   s1, 4(sp)         # restaura en orden inverso
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret                    # jalr zero, 0(ra)

Checklist:

  1. ¿Mi función llama a otra? → guarda ra.
  2. ¿Uso s0–s11? → guárdalos y restáuralos.
  3. ¿Uso t0–t6 o a0–a7 después de una llamada? → guárdalos antes de llamar.
  4. ¿El stack queda alineado a 16 bytes? → sí, usa múltiplos de 16.
  5. ¿Restauro sp exactamente como estaba? → sí.

7. RV32F (floats)

  • 32 registros f0–f31: ft0–ft11 (temporales), fs0–fs11 (saved), fa0–fa7 (args).
  • flw rd, off(rs1) / fsw rs2, off(rs1) → carga/guarda float; la dirección va en un registro entero (rs1), el dato en un registro float.
  • Operaciones: fadd.s, fsub.s, fmul.s, fdiv.s, fsqrt.s, fmin.s, fmax.s.
  • Conversión: fcvt.s.w rd, rs1 (int → float), fcvt.w.s rd, rs1 (float → int, trunca).
  • Movimiento: fmv.s.x rd, rs1, fmv.x.s rd, fs1, fmv.s rd, fs1.
  • Comparación: feq.s, flt.s, fle.s → resultado en registro entero (0/1).
  • fcsr contiene flags de excepción y modo de redondeo (frm).

8. Leer código: qué buscar

  1. Prólogo: addi sp, sp, -N, sw ra, ..., sw s0, ... → función con stack frame.
  2. Argumentos: usa a0, a1, ... al inicio.
  3. Loop: un label, un branch hacia atrás y un contador (addi t0, t0, 1).
  4. Array: slli t0, i, 2 + add t1, base, t0 + lw t2, 0(t1).
  5. Llamada: jal ra, func o call func; después usa a0 como resultado.
  6. Epílogo: restaura ra, s*, sp, luego ret.
  7. Recursión: busca que se guarde ra y los argumentos en el stack antes de la llamada recursiva.

Ejemplo: suma de un arreglo

# a0 = base, a1 = n; retorna suma en a0
sum:
    li   t0, 0          # i = 0
    li   t1, 0          # suma = 0
loop:
    bge  t0, a1, done   # si i >= n, termina
    slli t2, t0, 2      # t2 = i * 4
    add  t2, a0, t2     # t2 = base + i*4
    lw   t3, 0(t2)      # t3 = A[i]
    add  t1, t1, t3     # suma += A[i]
    addi t0, t0, 1      # i++
    j    loop
done:
    mv   a0, t1         # retorno
    ret

9. Errores típicos

  • lw t0, t1 → falta offset(base); debe ser lw t0, 0(t1).
  • Usar addi con un inmediato fuera de −2048..2047; usa li o lui+addi.
  • Olvidar guardar ra antes de una llamada anidada.
  • Usar t registers después de una llamada sin guardarlos.
  • No restaurar sp al final.
  • Confundir jalr zero, 0(ra) (return) con jalr ra, 0(ra).
  • En branches, comparar con zero cuando se necesita otra constante: usa li en un registro.
  • Olvidar que lb sign-extiende y lbu no.
  • En RV32F, usar un registro entero para el dato float (debe ser f).
  • Creer que RISC-V tiene flags: no; los branches comparan registros.

I/O

Address decoder: entre bus y RAM/dispositivos; compara dirección, activa Chip Select, elige registro. Único punto de selección; el CPU no cambia.

RISC-V

Registros: zero, ra, sp, gp, tp, t0-6, s0-11, a0-7. ABI: t/a/ra caller-saved; s/sp callee-saved; args a0-a7; retorno a0. No hay flags: branches comparan registros (beq, bne, blt, bge, bltu, bgeu). Load/store: lw rd, off(rs1), sw rs2, off(rs1); no lw rd, rs1. Saltos: jal rd, label (call), jalr zero, 0(ra) (ret), j label. Pseudo: li, la, mv, not, neg, beqz, bnez, bgt, ble, ret, call, nop.
